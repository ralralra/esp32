# 동아리 박람회 출품 기준 — 무엇을 만들고 무엇을 대체하나

앱 기획안(후불제 시간제 대여, 10화면)을 **부스에서 실제로 돌아가는 데모**로 만들기 위한
현실성 점검표입니다. "못 하니까 뺀다"가 아니라 **관람객 눈에는 똑같이 보이는 대체안**을 씁니다.

## 대체 결정표

| 기획 요소 | 현실 문제 | 데모에서 쓰는 대체안 | 발표 때 할 말 |
|---|---|---|---|
| **계좌 자동 출금** | 실제 이체는 PG사 계약·사업자등록 필요 (학생 불가) | **가상 결제** — 계좌를 마스킹(123-***-9012)해 저장하고, 반납 시 payments 탭에 결제 기록 생성 | "결제 연동 지점까지 설계·구현했고, PG 계약만 붙이면 동작합니다" |
| **지도 + GPS 거리(50m/120m)** | 지도 API 키·과금, 실내 GPS 부정확 | **임의의 정적 지도 이미지** 위에 보관함 3곳 핀 고정 배치, 거리 표시는 고정값 | "위치 데이터는 lockers 탭에 이미 있어 실제 지도로 교체 가능" |
| **QR 코드 스캔** | 가능 — 대체 불필요 | 보관함에 **locker_id QR 인쇄해 부착** (`L001`), 앱은 html5-qrcode로 스캔 | 그대로 시연 |
| **보관함 3곳(L001~L003)** | 하드웨어 1대만 제작 가능 | **실물은 L001 1대**, L002·L003은 앱 화면에만 표시(데이터는 시트에 존재) | "확장은 보관함 행 추가 + 보드 1대 추가로 끝" |
| **우산 5개(01~05)** | 슬롯 4칸 하드웨어 | **4칸으로 조정** (UB001~UB004) — 앱 화면도 4개로 | — |
| **로그인/회원가입** | 비밀번호·인증 관리 부담 | **이름+전화번호 최초 1회 등록**, 전화번호가 곧 식별자 (기획안 그대로) | 기획대로 |
| **실시간 푸시 알림** | FCM 설정·서버 필요 | **앱 화면 내 안내 + 보드 LED** (성공 2회 점멸 / 실패 연속 점멸) | "알림 설계는 상태표로 정의됨" |
| **24~72시간 실사용 시연** | 부스에서 3일을 기다릴 수 없음 | **요금 계산은 분 단위 실제 계산** — 시연은 "몇 분 빌렸다 반납"으로 보여주고, 초과 요금은 시트에서 rental_time을 과거로 바꿔 시연 | "요금 로직은 실시간 계산, 시간만 압축 시연" |

## 하드웨어(ESP32)는 "선택 사항"이 맞나?

맞습니다. 이 백엔드는 **보드 없이도 전체 흐름이 완결**됩니다 (앱 → Apps Script → 시트).
보드를 연결하면 여기에 **실물 잠금 해제 + 우산 유무 자동 확인**이 얹히는 구조입니다.

| 시연 방식 | 필요한 것 | 관람객이 보는 것 |
|---|---|---|
| A. 앱만 | 폰 + 시트 | 화면 흐름 10단계, 요금 자동 계산, 내역 |
| B. 앱 + 보관함 (권장) | A + ESP32 보관함 | 위 + **실제로 문이 열리고 우산이 빠지면 대여완료** |
| C. 보관함만 | ESP32 + 시리얼 | 시리얼 `r1`/`b1`로 기구 동작 확인 (백업용) |

> 💡 **부스 운영 팁**: 네트워크가 불안한 부스를 대비해 C(시리얼 전용 모드)를 백업으로 두세요.
> 펌웨어가 WiFi 15초 실패 시 자동으로 시리얼 모드로 넘어갑니다.

## 앱(AI Studio) ↔ 백엔드 연결 규격

앱은 아래 주소만 호출하면 됩니다. **서버 주소는 구글 시트 `시트1` 탭의 `/exec` URL**입니다.

> 📱 **앱 화면별 연동 코드는 [`app/screens.md`](app/screens.md)에 정리했습니다.**
> 공통 호출 코드는 [`app/api.js`](app/api.js) — `SERVER_URL` 한 줄만 바꾸면 됩니다.

### ⚠ 먼저 할 일 — 배포된 코드 교체

현재 그 URL에 올라가 있는 코드는 **`getUmbrella` 하나만 동작하는 초기 버전**입니다.
(직접 호출해 확인: 다른 action은 전부 `{"success":false,"message":"올바른 action이 없습니다."}`)
즉 **지금은 앱에서 대여·반납·결제를 눌러도 서버가 처리하지 못합니다.**

거기에 더해 그 코드는 umbrellas 탭의 열을 한 칸씩 밀려 읽습니다:

| 응답 키 | 실제로 담긴 값 |
|---|---|
| `status` | 슬롯 번호 (1, 2, 3…) ← 상태가 아님! |
| `location` | 대여 상태 (available/rented) ← 위치가 아님! |

**교체 방법** (URL이 그대로 유지되는 방식):
1. 시트 → `확장 프로그램 → Apps Script`
2. 기존 코드를 전부 지우고 [`umbrella_locker.gs`](apps_script/umbrella_locker.gs) 붙여넣기
3. **배포 → 배포 관리 → (연필 아이콘) → 버전: 새 버전 → 배포**
   ※ "새 배포"를 누르면 URL이 바뀌어 앱 설정을 다시 해야 하니 주의!

**앱을 안 고쳐도 됩니다.** 새 코드는 기존 앱 호환을 위해
`getUmbrella`를 같은 응답 모양(`success`, `locker`, `status`, `location`)으로 그대로 유지하고,
뜻이 분명한 키(`slot_no`, `umbrella_status`, `locker_id`)를 **추가로** 넣어줍니다.
모든 응답에 `success`/`message`도 함께 담기므로 기존 앱 코드가 깨지지 않습니다.
앱을 손볼 때 새 키로 갈아타면 됩니다.

| 앱 화면 | 호출 | 돌아오는 값 |
|---|---|---|
| ② 정보 입력 | `?action=register&name=홍길동&phone=010-1234-5678` | `user_id` (같은 번호면 기존 ID) |
| ⑦ 계좌 등록 | `?action=register_account&user_id=U001&account=123-456-789012` | `account_masked` |
| ③ 보관함 찾기 | `?action=lockers` | 보관함 목록 (이름·위치·빈 슬롯) |
| ⑤ 우산 선택 | `?action=status&locker_id=L001` | 그 보관함 우산 목록 + 상태 |
| ⑥⑧ 대여 | `?action=rent&user_id=U001&locker_id=L001&umbrella_id=UB002&plan_id=P001` | `rental_id`, `slot_no`, `expected_return` |
| ⑨⑩ 반납·결제 | `?action=return&user_id=U001` | `duration_min`, `amount`(초과요금 포함), `payment_id` |
| 내역 | `?action=history&user_id=U001` | 이용 기록 + 결제 기록 |
| 요금제 | `?action=plans` | 요금제 목록 (시트 plans 탭) |
| (기존 앱 호환) | `?action=getUmbrella&umbrella_id=UB001` | 우산 1개 정보 — 예전 응답 모양 유지 |

- 전부 GET/POST 모두 동작 — AI Studio에서 `fetch(URL + "?action=...")` 한 줄이면 됩니다
- 요금 계산: **요금제 가격 + (초과 시간 ÷ 24시간, 올림) × extra_24h_price**
- 대여 시 ESP32 명령(`RENT:슬롯`)이 자동으로 큐에 쌓입니다 — 보드가 없으면 그냥 무시됩니다

## 부스 시작 전 체크리스트

1. **시트 정리** — umbrellas 탭의 형식 깨진 행(`U001 | 01번 | 대여 가능`) 삭제,
   UB004의 `rented`/`U002`를 `available`/빈칸으로, R001 테스트 행 삭제
2. **데모 리셋** — 스크립트 편집기에서 `resetDemo()` 실행 (rentals·payments 비우고 우산 전부 available)
   → 관람객이 바뀔 때마다 한 번씩 눌러주면 깨끗한 상태로 시연 가능
3. 보드: WiFi 이름·비번과 `/exec` URL 확인 후 업로드, 시리얼에서 `s`로 4칸 감지 확인
4. 우산에 자석 부착 위치 최종 고정 (리드스위치 감지 거리 약 1cm)

## 남은 선택 과제 (여유 있으면)

- daily_stats 탭 자동 집계 (일별 대여/반납 수, 인기 보관함)
- 연체 표시: `expected_return`이 지난 active 대여를 앱에서 빨갛게
- 관리자 화면: 전체 보관함 상태 한눈에 보기
