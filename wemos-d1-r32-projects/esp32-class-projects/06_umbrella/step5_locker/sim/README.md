# 시뮬레이터 — 보드 없이 스케치 돌려보기

`step5_locker.ino`를 **그대로** PC에서 컴파일해 실행합니다.
서보·리드스위치·시계·서버를 흉내내서, 대여·반납이 시간 순서대로 어떻게
흘러가는지 눈으로 볼 수 있어요.

```bash
make run
```

## 무엇을 확인할 수 있나

| 확인되는 것 | 확인 못 하는 것 |
|---|---|
| 대여·반납 상태 흐름과 타이머 | **전류·전압** (실물 전원 문제) |
| 서보를 언제 몇 도로 돌리는지 | 서보의 실제 토크·기구 간섭 |
| 서버로 나가는 요청(`cancel`·`return_failed`) | WiFi 연결·구글 시트 응답 |
| 앱 명령 해석 (`RENT:L001:2` / 남의 보관함 무시) | 리드스위치의 실제 감지 거리 |

> ⚠ **여기서 전부 통과해도 실물이 안 움직일 수 있습니다.**
> 그건 코드가 아니라 전원·배선 문제라는 뜻이에요.
> → [`../README.md`](../README.md)의 "서보가 전혀 안 움직일 때" 참고

## 돌려보는 시나리오

| # | 상황 |
|---|---|
| 0 | 전원 켜기 — 네 칸을 차례로 잠그고 힘 빼기 |
| 1 | 대여 성공 — 우산을 꺼내면 5초 뒤 잠김 |
| 2 | **대여 불가** — 그 칸에 우산이 없음 (서보가 안 움직이는 유일한 경우) |
| 3 | 대여 타임아웃 — 30초간 안 가져감 → 자동 잠금 + 대여 취소 |
| 4 | 반납 성공 — 꽂자마자 즉시 잠김 |
| 5 | 반납 재시도 — 3번 열어주고 실패 → 반납 취소 |
| 6 | 반납 타임아웃 — 30초간 안 꽂음 → 반납 취소 |
| 7 | 앱 명령 — 내 보관함(`L001`)만 실행, `L002`는 무시 |
| 8 | **PWM 채널 고갈** — 12번 여닫아도 계속 움직이는지 (붙였다 뗐다 하면 마릅니다) |
| 9 | PWM 타이머를 안 잡았을 때 — "열림"은 찍히는데 서보는 안 움직이는 증상 재현 |

## 어떻게 동작하나

`sim_main.cpp`가 `../step5_locker.ino`를 `#include`하고,
`stubs/`의 가짜 헤더들이 아두이노 API를 대신합니다.

- `millis()`는 **가상 시계** — 30초 타임아웃도 즉시 검사됩니다
- `Servo`는 각도만 기록 — **`attach` 실패와 채널 고갈까지 재현**합니다
  (`detach()`해도 채널을 안 돌려주는 라이브러리 동작을 그대로 흉내냅니다)
- `WiFi`는 항상 연결 안 됨 → 통신 태스크를 안 띄우고, 나가는 요청은 큐에서 꺼내 출력
- 리드스위치는 `digitalRead`가 돌려줄 값을 시나리오가 직접 바꿉니다

**스케치를 고치면 여기도 같이 돌려보세요.** 로직이 깨지면 바로 잡힙니다.
