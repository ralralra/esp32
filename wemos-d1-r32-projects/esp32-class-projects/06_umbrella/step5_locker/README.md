# 5단계 — 스마트 보관함 (서보 잠금 + 리드스위치 + 구글 시트 DB)

슬롯 4칸 보관함입니다. 슬롯마다 **서보(잠금)와 리드스위치(우산 감지)가 짝**을 이룹니다.
리드스위치가 감지되면(자석 가까이) 우산 있음, 감지 안 되면 우산 없음.

## 동작 규칙

**대여** — 앱(또는 시리얼)에서 대여 버튼:
```
슬롯 열림(0도) → 우산을 꺼내면 5초 뒤 닫힘(180도) → 확인
  우산 없음   → ✓ 대여완료
  30초간 안 가져감 → 닫고 ✗ 대여실패 + 시트의 대여 기록 자동 취소
```

**반납** — 해당 우산의 반납 버튼:
```
슬롯 열림 → 우산이 꽂히면 **즉시** 닫힘 → 확인 (우산을 잡아주는 기구가 없어서)
  우산 감지  → ✓ 반납완료
  감지 안 됨 → 다시 열림 (최대 3회, 그래도 없으면 반납실패)
  30초간 안 꽂음 → 닫고 반납실패
```

기다리는 동안에도 보드가 멈추지 않습니다(논블로킹). 통신은 별도 코어에서 돌아가므로
WiFi가 느려도 센서 감지와 타이머가 밀리지 않습니다.

각도(180=잠김/0=열림), 5초, 자동 닫힘(30초), 반복 횟수(3회)는 코드 위쪽 상수만 바꾸면 됩니다.

전체 실행 로직 순서도 → **[`flowchart.md`](flowchart.md)**
박람회 출품 기준 현실성 점검·대체안 → **[`EXPO_PLAN.md`](EXPO_PLAN.md)**

## 명령 넣는 두 가지 방법

| 방법 | 대여 | 반납 | 상태 보기 |
|---|---|---|---|
| 앱 → Apps Script 명령 큐 (1.5초 폴링) | `RENT:L001:2` | `RETURN:L001:2` | — |
| **시리얼 모니터 (115200)** | `r1`~`r4` | `b1`~`b4` | `s` |

> 💡 명령에는 **보관함 번호**가 함께 들어갑니다(`RENT:L001:2`).
> 슬롯 번호 1~4는 보관함마다 겹치기 때문에, 번호만 보내면 L002에서 빌린 명령을
> L001 보드가 집어가 엉뚱한 칸이 열려요. 보드는 자기 `LOCKER_ID`와 맞는 명령만
> 꺼내가고, 남의 명령은 큐에 그대로 남겨둡니다.

서보·전원 점검용으로 **`o1`~`o4`(그냥 열기)**, **`c1`~`c4`(그냥 닫기)** 도 있습니다.
대여·반납 처리 없이 모터만 움직이므로, 열어둔 채 전압을 재보기 좋아요.

동작할 때마다 시리얼에 이렇게 찍힙니다 — 서보가 명령을 받았는지 눈으로 확인할 수 있어요:

`r1` 입력 (대여)
```
슬롯1 열림
5초후 닫힘
대여완료
```

`b1` 입력 (반납) — 우산을 꽂으면 바로 닫고 확인합니다
```
슬롯1 열림
닫힘
반납완료
```

WiFi가 안 잡혀도 시리얼 명령은 그대로 동작하므로, 앱 없이 배선·기구 테스트가 가능합니다.
(연결되면 자동으로 앱 명령도 받기 시작합니다)

## 준비물

- Wemos D1 R32 + **아두이노 센서쉴드** + USB
- **서보모터(SG90) ×4** — 슬롯 잠금
- **리드스위치 ×4** + 자석 — 우산 거치 감지
- 외부 5V 전원 (실드 EXT PWR 단자에 연결) — 서보용
- 구글 시트 DB (users / lockers / umbrellas / rentals / plans 탭)

배선 → **[`../docs/wiring_servo_reed.md`](../docs/wiring_servo_reed.md)**
(센서쉴드 기준: 서보 = 실드 5·4·3·2 자리, 리드 = 9·7·6·A1 자리)

## 세팅 순서

### ① 구글 시트 준비
DB 시트에 아래 탭과 제목 행이 있어야 합니다 (열 **순서**는 달라도 OK — 코드가 제목으로 찾음):

| 탭 | 꼭 필요한 열 |
|---|---|
| users | user_id, name, status |
| lockers | locker_id, total_slots, available_slots, last_update |
| umbrellas | umbrella_id, locker_id, slot_no, status, last_check_time, total_rentals, last_user_id |
| rentals | rental_id, user_id, umbrella_id, locker_id, slot_no, plan_hours, plan_price, rental_time, expected_return, return_time, duration_min, status, payment_status |
| plans | plan_id, plan_name, hours, price, extra_24h_price, status |

- `commands` 탭은 **자동 생성**됩니다 (ESP32 명령 대기줄 — 위에서부터 차례로 실행)
- umbrellas의 status는 `available` / `rented` **영어로 통일**하세요

### ①-1 빈 시트로 새로 시작한다면 — `setupSheets()` 한 번
탭을 손으로 만들 필요 없이, Apps Script 편집기에서 함수 목록에서
**`setupSheets`를 골라 실행(▶)** 하면 위 탭 전부(제목 행 + 보관함 L001·우산 4개·
요금제 3종 기본 데이터)가 자동으로 만들어집니다. 이미 있는 탭은 건드리지 않아요.

### ② Apps Script 배포
1. 시트에서 `확장 프로그램 → Apps Script` → [`apps_script/umbrella_locker.gs`](apps_script/umbrella_locker.gs) 붙여넣기
2. 탭 이름이 다르면 코드 맨 위 `TAB` 설정만 수정
3. `배포 → 새 배포 → 웹 앱` / **액세스 권한: 모든 사용자** → **/exec URL 복사**

### ②-1 부품이 의심되면 — 1번 슬롯만 단독 테스트
서보·리드가 하나라도 이상하면 [`test_slot1/test_slot1.ino`](test_slot1/test_slot1.ino)를 먼저 올려보세요.
WiFi·서버 없이 1번 슬롯(서보 GPIO16 + 리드 GPIO13)만 확인합니다:
자석을 대면 즉시 "우산 있음/없음"이 찍히고, `o`/`c`/`t`(대여 흐름)/`w`(왕복 10회 — 전원 스트레스) 명령을 씁니다.
`w`가 10회를 완주하면 전원은 충분한 겁니다.

### ③ 시리얼로 먼저 테스트 (WiFi·앱 없이!)
업로드 후 시리얼 모니터(115200)에서:
```
s     → 슬롯 4칸의 우산 유무가 맞게 나오는지 (자석을 대보며 확인)
r1    → 슬롯 1 열림 → 우산을 꺼내면 5초 뒤 닫힘 → "대여완료"
b1    → 슬롯 1 열림 → 우산을 꽂으면 즉시 닫힘 → "반납완료"
        (안 꽂으면 다시 열림 3회까지, 30초 지나면 자동 잠금)
```

### ④ 앱 연결
[`step5_locker.ino`](step5_locker.ino)에서 WiFi 이름·비번, **/exec URL**, 그리고
**`LOCKER_ID`**(이 보드가 담당할 보관함 — 시트 lockers 탭의 값, 기본 `L001`)를 확인 후 업로드.
라이브러리: **ESP32Servo** (기본 Servo.h는 ESP32에서 안 됩니다!)

## API 정리 (Apps Script)

| 요청 | 누가 | 하는 일 |
|---|---|---|
| `?action=register&name=..&phone=..` | 앱 | 회원 등록 (같은 번호면 기존 user_id 반환) |
| `?action=register_account&user_id=..&account=..` | 앱 | 결제 계좌 등록 (마스킹 저장) |
| `?action=lockers` | 앱 | 보관함 목록 |
| `?action=rent&user_id=U001&locker_id=L001&umbrella_id=UB002` | 앱 | 지정 우산 대여 → rentals 추가 + umbrellas·lockers 갱신 + `RENT:슬롯` 명령 |
| `?action=return&user_id=U001` | 앱 | 반납 + **후불 정산** (이용시간·초과요금 계산 → payments 기록) + `RETURN:슬롯` |
| `?action=history&user_id=U001` | 앱 | 이용·결제 내역 |
| `?action=status&locker_id=L001` | 앱 | 우산 현황 JSON |
| `?action=cmd&locker_id=L001` | ESP32 | **자기 보관함 명령만** 읽기 (읽으면 그 줄이 지워짐) |
| `?action=report&locker_id=L001&p1=1&p2=0…` | ESP32 | 슬롯별 우산 유무 보고 → last_check_time 갱신 + **어긋난 상태 자동 보정**(빌린 사람 없는 `rented` 복구, `available_slots` 재계산) |
| `?action=plans` | 앱 | 요금제 목록 (시트 plans 탭) |
| `?action=cancel&locker_id=L001&slot=2` | ESP32 | **대여실패 롤백** — 우산이 안 빠졌을 때 rentals·umbrellas·lockers 원상복구 |
| `?action=return_failed&locker_id=L001&slot=2` | ESP32 | **반납실패 롤백** — 우산이 안 들어왔을 때 반납·정산을 되돌려 다시 대여 중으로 |

- 요금제: `&plan_id=P002` 추가 가능 (기본 P001=24시간)
- **정합성 규칙**: rentals·umbrellas·lockers는 항상 스크립트가 한 번에 갱신합니다.
  시트를 손으로 고치면 상태가 어긋나요! (LockService로 동시 요청도 방지)

## 시트 정리 — 무엇을 지워도 되나

탭은 두 종류입니다. **설정 데이터**는 지우면 시스템이 멈추고, **기록 데이터**는 지워도 됩니다.

| 탭 | 지워도 되나 | 지우면 생기는 일 |
|---|:---:|---|
| 시트1 (`/exec` 주소) | ❌ | 앱·보드에 넣을 서버 주소를 잃습니다 |
| **lockers** | ❌ | 보관함 목록이 비어 앱 화면 ③이 빈 화면, 대여 불가 |
| **umbrellas** | ❌ | 빌릴 우산이 없어져 대여 불가 |
| **plans** | ❌ | 요금제 화면이 비고, 요금 계산 기준이 사라짐 |
| users | △ | 지워도 되지만 앱에서 다시 가입해야 함 |
| rentals | ⭕ | 단, umbrellas·lockers도 함께 되돌려야 함 (아래 참고) |
| payments | ⭕ | 결제 내역만 사라짐 |
| daily_stats | ⭕ | |
| commands | ⭕ | 헤더만 남기고 지우는 게 오히려 권장 |
| `deviceId·command·status` 탭 | ⭕ | **옛 프로토타입 잔재 — 지우세요.** 지금 코드는 이 탭을 읽지 않습니다 (`L001 / LOCK / DONE` 같은 줄이 남아 있어도 아무 영향 없음) |

### ⚠ rentals만 손으로 지우면 우산이 잠깁니다

`rentals`를 비워도 `umbrellas`에 `rented`로 남아 있으면 **그 우산은 영원히 빌릴 수 없습니다.**
대여 기록·우산 상태·보관함 잔여 수는 항상 세트로 움직여야 해요.

### ✅ 그래서 손으로 지우지 말고 `resetDemo()`

Apps Script 편집기에서 함수 목록에서 **`resetDemo`를 골라 실행(▶)** 하면 한 번에 정리됩니다:

- `rentals`·`payments` 비우기 (헤더는 유지)
- 모든 우산을 `available`로, 빌린 사람 기록 지우기
- 보관함 잔여 슬롯을 전체 슬롯 수로 복구
- 남은 명령 대기줄 비우기

**회원(`users`)은 지우지 않습니다** — 시연할 때마다 다시 가입하지 않아도 되도록.
회원까지 초기화하려면 `users` 탭만 손으로 지우고, 앱에서 다시 가입하세요.

> 💡 처음 만들 때 손으로 넣은 테스트 줄(`umbrellas`의 `U001 | 01번 | 대여 가능`,
> `rentals`의 R001)은 형식이 맞지 않으니 **지우는 게 맞습니다.**

## 문제 해결 — 앱은 되는데 모터가 안 움직일 때

**먼저 시리얼에서 `s` 와 `n` 을 눌러보세요.** 통신이 살아 있는지 바로 나옵니다.

```
── 통신 상태 ──
  WiFi: 연결됨
  서버: 확인 412회 · 마지막 응답 200 · 연속실패 0회
  마지막 성공: 1초 전                  ← 여기까지 정상이면 통신 문제가 아닙니다
```

| `s` 가 이렇게 나오면 | 뜻 |
|---|---|
| `서버: 아직 한 번도 확인 못 함` | 보드가 서버에 한 번도 못 닿음 → 배포 URL·와이파이 확인 |
| `연속실패`가 계속 늘어남 | 닿았다 끊김 → 아래 ②③ |
| `마지막 성공: n초 전` (n이 작음) | **통신은 정상** → 원인은 리드스위치나 전원 |

**앱에서 대여를 누른 직후 `n`** 을 누르면 그 명령이 실제로 오는지 바로 보입니다.

```
서버에 물어보는 중...
  응답 코드 200 (412ms)
  받은 명령: RENT:L001:2 — 바로 실행합니다        ← 명령은 오고 있음
```
```
  응답 코드 200 (380ms)
  대기 중인 명령 없음 — 서버와 통신은 정상입니다   ← 서버가 명령을 안 만든 것 (⓪ 참고)
```

**그다음 시트의 `commands` 탭을 보세요.** 여기서 원인이 갈립니다.

| commands 탭 상태 | 뜻 | 할 일 |
|---|---|---|
| 명령이 쌓인 채 안 없어짐 | 앱·서버는 정상, **보드가 서버에 연결 안 됨** | 아래 ①②③ |
| 명령이 바로 사라짐 | 보드가 받아감 → **모터·전원 문제** | 아래 ④ |
| 애초에 안 쌓임 | **서버가 대여를 거절했거나 앱이 서버를 못 부름** | 아래 ⓪ |

보드는 1.5초마다 명령을 가져갑니다. 명령이 1분 넘게 남아 있으면 보드가 못 오고 있는 겁니다.

### ⓪ 명령이 아예 안 쌓일 때 — 서버가 거절한 겁니다

가장 흔한 원인은 **그 계정이 아직 반납을 안 한 것**입니다. 한 사람은 한 번에
한 개만 빌릴 수 있어서, 미반납이 남아 있으면 서버가 `이미 대여 중이에요`만
돌려주고 **명령을 만들지 않습니다.** 그래서 모터가 전혀 안 움직여요.
(시리얼 `r1`은 서버를 안 거치니까 잘 움직이는 것과 대비됩니다)

브라우저 주소창에 아래를 넣어 무엇이 막고 있는지 바로 볼 수 있습니다:

```
배포URL?action=history&user_id=U001      ← status가 active인 줄이 남아 있나?
배포URL?action=status&locker_id=L001     ← 빌릴 수 있는(available) 우산이 있나?
```

| 서버가 돌려준 말 | 뜻 | 할 일 |
|---|---|---|
| `이미 대여 중이에요` | 그 계정에 미반납이 있음 | 앱에서 **반납 먼저** — 안 되면 `resetDemo()` |
| `UB00n는 지금 대여할 수 없어요` | 그 우산이 `rented`로 잠겨 있음 | 30초 뒤 자동 보정됨 · 급하면 `resetDemo()` |
| `등록되지 않은 사용자` | 폰에 저장된 user_id가 시트에 없음 | 앱에서 회원가입 다시 |
| 아무 응답 없음 | 앱이 서버를 못 부름 | 브라우저 콘솔에서 CORS·주소 확인 |

> 💡 **부스에서 가장 빠른 초기화** — Apps Script 편집기에서 `resetDemo()` 실행.
> rentals·payments를 비우고 우산을 전부 `available`로, 명령 큐까지 정리합니다.
> (users는 지우지 않으니 폰에 저장된 계정은 그대로 씁니다)

> 🧪 **코드가 원인인지 먼저 걸러내려면** — [`sim/`](sim) 시뮬레이터를 돌려보세요.
> 보드 없이 PC에서 이 스케치를 그대로 실행해 대여·반납 흐름을 확인합니다.
> ```bash
> cd sim && make run
> ```
> 여기서 전부 통과하면 **로직에는 문제가 없다**는 뜻이고, 남는 건 전원·배선입니다.

### ⓪-1 시리얼 `o1`을 눌러도 서보가 전혀 안 움직일 때

`o1`~`o4`(그냥 열기)는 서버도 리드스위치도 거치지 않고 **서보만 돌립니다.**
이것마저 안 움직이면 원인은 셋 중 하나예요. 위에서부터 확인하세요.

**1) 켤 때 네 칸이 한 번씩 움직이나요?**

전원을 넣으면 `슬롯1 잠금` … `슬롯4 잠금`이 찍히면서 네 개가 차례로 한 번씩 돕니다.
**여기서부터 안 움직이면 명령 문제가 아니라 서보·전원·라이브러리 문제입니다.**

**2) `⚠ 슬롯n 서보 연결 실패` 가 찍히나요?**

```
슬롯4 열림
⚠ 슬롯4 서보 연결 실패 — GPIO26에 PWM을 못 잡았어요
```

이러면 **명령은 잘 왔는데 서보만 안 움직이는** 상태입니다. 원인은 둘입니다.

**② -1 붙였다 뗐다 하다가 PWM 채널이 마른 경우** ← 실제로 겪은 원인

ESP32Servo 일부 버전은 `detach()`할 때 PWM 채널을 **반납하지 않습니다.**
그래서 부팅 때 네 칸을 붙였다 떼고 나면, 그다음 명령부터 `attach()`가 전부 실패해요.
겉으로는 "WiFi도 되고 명령도 오는데 모터만 안 움직인다"로 보입니다.

```cpp
constexpr bool RELEASE_WHEN_IDLE = false;   // ← 기본값. 붙인 채로 유지합니다
```

`false`면 `setup()`에서 **한 번만 붙이고 계속 씁니다.** 다시 attach하지 않으니
채널이 마르지 않아요. 서보가 뜨겁거나 계속 떠는 게 더 문제라면 `true`로 바꿔보되,
위 증상이 다시 나오는지 확인하세요.

**② -2 타이머를 아예 안 잡은 경우**

라이브러리 매니저에서 **ESP32Servo (Kevin Harrington)** 가 설치돼 있는지 확인하세요.
기본 `Servo.h`는 ESP32에서 동작하지 않습니다.

> 이 스케치는 `setup()`에서 `ESP32PWM::allocateTimer(0~3)`으로 타이머를 미리 잡습니다.
> 이 줄이 없으면 라이브러리 버전에 따라 `attach()`가 **조용히 실패**합니다.

> 🧪 두 경우 모두 [`sim/`](sim) 시뮬레이터가 재현합니다 (시나리오 8·9).
> `RELEASE_WHEN_IDLE`을 `true`로 바꾸고 `make run` 하면 실패하는 걸 볼 수 있어요.

**3) 아무 메시지 없이 조용하면 — 전원입니다**

서보를 **전부 뽑은 상태**로 실드 **V핀 ↔ G핀** 전압을 재보세요.

| 잰 값 | 뜻 | 할 일 |
|---|---|---|
| 4.8~6.0V | 정상 | 배선(주황=S / 빨강=V / 갈색=G) 방향 확인 |
| 0V | 외부 전원이 안 들어옴 | 실드 **전원 선택 점퍼를 외부(EXT)** 로 |
| 3.3V 근처 | 보드 전원에서 끌어옴 | 서보 4개엔 부족 — 외부 5V 2A 이상 필요 |
| 6V 초과 | ⚠ 위험 | **서보 꽂지 마세요** — 5V로 낮춘 뒤에 |

⚠ **GND 공통 접지**를 빼먹으면 전압은 정상인데 서보가 신호를 못 알아듣습니다.
외부 전원 GND와 보드 GND를 반드시 연결하세요.

**4) 그래도 안 되면 — 한 개만 떼어서**

[`test_slot1/`](test_slot1) 스케치를 올려 슬롯1만 단독으로 돌려보세요.
여기서 움직이면 전원 용량(4개 동시) 문제, 여기서도 안 움직이면 그 서보·배선 문제입니다.

### ⓪-1b `test_slot1`은 움직이는데 본 스케치는 안 움직일 때

두 스케치의 차이는 사실상 **둘뿐**입니다.

| | `test_slot1` | `step5_locker` |
|---|---|---|
| 서보 개수 | 1개 | **4개** |
| WiFi | **안 씀** | 씀 (계속 폴링) |

그러니 원인도 둘 중 하나입니다. **`ENABLE_WIFI`로 한 번에 가릅니다.**

```cpp
constexpr bool ENABLE_WIFI = false;   // 코드 맨 위 "1. 바꿀 곳"
```

이렇게 올리면 WiFi를 아예 안 켜고 시리얼 명령만 받습니다
(`test_slot1`과 같은 조건 + 서보 4개).

| `ENABLE_WIFI = false`로 하면 | 원인 | 할 일 |
|---|---|---|
| **잘 움직인다** | WiFi가 켜지면서 전원이 모자람 | 아래 "전류가 모자랄 때" |
| 여전히 안 움직인다 | 서보 4개를 감당 못 하는 전원, 또는 배선 | 서보를 1~2개만 꽂고 다시 |

> 💡 발표장에 인터넷이 없을 때도 `ENABLE_WIFI = false`로 두고
> 시리얼(`r1`·`b1`)로만 시연할 수 있습니다.

**전류가 모자랄 때 — 전압만 보면 속습니다**

서보를 뽑고 잰 **5V는 "무부하 전압"** 입니다. 서보가 돌기 시작하는 순간
순간 전류가 서보 하나당 **0.5~1A**까지 튀는데, 어댑터나 배선이 그걸 못 대면
전압이 순간 3V대로 주저앉아 **서보가 아예 안 돌거나 부르르 떨기만 합니다.**

| 확인 | 정상 |
|---|---|
| 어댑터 정격 | 서보 4개면 **5V 3A 이상** (2A는 빠듯합니다) |
| USB 전원으로 서보까지 돌리는 중? | ❌ USB는 0.5A — **반드시 별도 5V** |
| 전선 굵기·악어클립 | 가늘거나 접촉이 헐거우면 그 자체로 전압 강하 |
| 서보를 1개만 꽂으면 되나? | 된다면 **용량 부족 확정** |

`o1`→`o2`→`o3`→`o4`를 **하나씩 천천히** 눌러보세요.
하나씩은 되는데 연속으로 하면 멈춘다 → 전류 부족입니다.

### ⓪-2 명령은 사라지는데 서보가 안 움직일 때 — 리드스위치를 보세요

**서보를 아예 안 움직이고 끝나는 경로는 딱 하나입니다:**
대여 명령을 받았는데 **그 칸에 우산이 없다고 판단**한 경우예요.
이때 보드는 문을 열지 않고 서버에 취소를 보냅니다.

시트에서 이렇게 보이면 이 경우가 확실합니다:

| 어디 | 무엇이 보이나 |
|---|---|
| `commands` 탭 | 비어 있음 (보드가 가져갔다는 뜻 — **통신은 정상**) |
| `rentals` 탭 | 방금 만든 줄이 `canceled` / `canceled`로 바뀌어 있음 |

> `canceled`로 바뀌는 길은 보드가 보내는 `?action=cancel` 하나뿐입니다.
> 그러니 이 표시가 보이면 **앱 → 서버 → 보드까지는 전부 잘 갔다는 증거**예요.

**할 일 — 시리얼 모니터에서 `s` 를 눌러보세요.**

```
── 슬롯 상태 ──
  슬롯1: 우산 없음      ← 실제로는 우산이 꽂혀 있는데 이렇게 나오면 원인 확정
```

| 원인 | 확인 | 고치기 |
|---|---|---|
| 자석이 너무 멂 | 자석을 리드에 바짝 붙이고 `s` 다시 | 감지 거리는 **1cm 안팎** — 우산과 센서 위치를 맞춰 고정 |
| 배선이 빠짐 | 리드 두 다리가 **GPIO ↔ GND**에 물렸는지 | 실드 자리: 슬롯1~4 = **9 · 7 · 6 · A1** (S와 G만, V는 안 씀) |
| 센서 방향이 반대 | 자석을 떼면 `우산 있음`이 되나 | 코드의 `REED_ACTIVE_LEVEL`을 `HIGH`로 |
| A2~A5에 꽂음 | 슬롯4가 계속 `우산 없음` | **A1(GPIO4)**이어야 합니다 — A2~A5는 내부 풀업이 없어요 |

대여를 눌렀을 때 시리얼에도 원인이 함께 찍힙니다:

```
슬롯1 대여불가 — 우산이 없어요 (리드 GPIO13=HIGH, 감지 기준=LOW)
  자석을 리드에 1cm 안으로 붙이고 s 를 눌러 다시 확인해보세요
```

`o1`(그냥 열기)은 이 검사를 건너뛰므로, **`o1`은 되는데 `r1`은 안 되면 리드 문제입니다.**

### ① 시리얼 모니터로 보드 상태 확인 (제일 먼저!)
USB를 연결하고 시리얼 모니터를 **115200**으로 연 뒤 보드의 EN(리셋) 버튼을 누르세요.

| 나오는 메시지 | 뜻 |
|---|---|
| `WiFi 연결 완료 — 앱 명령 대기!` | 정상 — ④로 |
| `WiFi 없음 — 시리얼 전용 모드` | WiFi 실패 → ② |
| 아무것도 안 나옴 | 업로드가 안 됐거나 보드 전원 문제 |

### ② WiFi가 안 잡힐 때
- **ESP32는 5GHz WiFi에 연결할 수 없어요.** 반드시 **2.4GHz**를 쓰세요.
  폰 핫스팟이면 설정에서 대역을 2.4GHz로 바꿔야 합니다. (가장 흔한 원인!)
- 학교 WiFi처럼 로그인 페이지가 뜨는 곳은 연결이 안 됩니다 → 폰 핫스팟 권장
- 코드의 `WIFI_SSID` / `WIFI_PASS` 오타 확인

### ③ 주소·보관함 번호 확인
- `URL`이 아직 `.../XXXX/exec` 그대로면 서버에 못 갑니다 → 시트 `시트1` 탭의 주소로 교체
- `LOCKER_ID`가 시트 `lockers` 탭의 값과 같은지 (기본 `L001`)

### ④ 모터가 도는지만 따로 확인
시리얼 모니터에 **`o3`** 입력 → 3번 칸이 열리면 모터·배선은 정상입니다. (`c3`으로 닫기)

**로그는 나오는데 모터가 안 움직이면** 명령은 갔다는 뜻이니 전원·배선 문제입니다.
`o3`으로 열어둔 상태에서 **실드 V-G 전압을 재보세요** — 5V 아래로 떨어지면 전원 부족입니다.

**모터가 이상하게 움직일 때는 증상으로 원인을 가릅니다** — 시리얼을 보면서 돌려보세요.

| 증상 | 원인 | 해결 |
|---|---|---|
| 움직이는 순간 시리얼에 **부팅 메시지가 다시 뜸** | 전원 부족 (보드가 리셋됨) | 외부 5V 2A 이상 |
| 부르르 떨리기만 하고 힘이 없음 | 전원 부족 또는 공통 접지 누락 | 아래 확인 |
| 하나씩은 잘 도는데 여러 개 쓰면 이상 | 전원 용량 부족 | 외부 5V 2A 이상 |
| 끝까지 안 가고 걸린 채 웅웅거림 | **기구 간섭** (전원 아님) | 걸쇠 위치·각도 조정 |
| 아예 무반응 | 배선 (신호선 자리 틀림) | 실드 5·4·3·2 자리 확인 |

**전원 기준**: SG90 하나가 움직이는 순간 최대 **0.7A** 정도를 먹습니다.
USB(5V 0.5A)로는 한 개도 빠듯해요. **5V 2A 이상 어댑터**나 건전지팩을 쓰세요.

> ❌ **12V 어댑터를 보드 DC잭에 꽂지 마세요.** 그 12V가 5V 핀·실드 V줄로 그대로 나와
> 서보(4.8~6V)를 태울 수 있습니다. 12V밖에 없다면 벅 컨버터(LM2596)로 5V를 만들어 쓰세요.
> 자세한 이유와 확인 방법 → [`../docs/wiring_servo_reed.md`](../docs/wiring_servo_reed.md)

- 서보 전원을 **외부 5V**에서 받고 있는지 (보드 전원으로는 못 돌립니다)
- 외부 전원의 **GND와 보드 GND가 연결**돼 있는지
  (공통 접지 — 빠지면 서보가 신호를 못 알아들어 떨리기만 합니다)

> 💡 코드에서 `RELEASE_WHEN_IDLE = true`면 **대기 중에는 서보 힘을 빼둡니다.**
> 전류·떨림·발열이 크게 줍니다. 문을 손으로 못 열게 계속 버텨야 한다면 `false`로 바꾸세요
> (대신 전원이 넉넉해야 합니다).

### ⑤ 밀린 명령 정리
보드가 꺼져 있는 동안 누른 명령이 큐에 그대로 쌓입니다.
연결되는 순간 **오래된 것부터 실행**되므로, 엉뚱한 칸이 열릴 수 있어요.
→ 시트 `commands` 탭에서 **헤더(1행)만 남기고 나머지 줄을 지우세요.**
