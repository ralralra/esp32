# 2단계 — 가상 결제 연출 + 주문번호

## 목표
[주문하기]를 누르면 **진짜 결제처럼 보이는 화면 연출**이 나오고, 마지막에 **주문번호**가 발급된다.
실제 결제는 없어요 — "결제 흐름의 체험"이 목적. (기획서 원칙: 실결제 ❌)

## 핵심 아이디어 — 결제는 '연출'로
```
[주문하기] → 💳 "카드를 리더기에 대주세요" (2초)
           → ⏳ "승인 중입니다..." (1.5초)
           → ✅ "결제 완료!" + 주문번호 + 주문 내역 영수증
```
카드사 연동 없이도, 손님이 겪는 **결제의 순서**는 그대로 체험할 수 있어요.
주문번호는 지금은 앱이 1번부터 차례로 발급 — 3단계에서 **DB(서버)가 발급**하도록 바꿉니다.

## 해보기
1. 1단계 앱을 연 채로, [`프롬프트.md`](프롬프트.md) 의 추가 지시를 AI Studio에 붙여넣기
2. 메뉴를 담고 [주문하기] → 결제 연출 3장면이 차례로 나오는지 확인
3. 결제 완료 화면의 주문번호가 주문할 때마다 1씩 커지는지 확인
4. [처음으로]를 누르면 장바구니가 비워지고 첫 화면으로 돌아오는지 확인

## 확인 ✅
- [ ] 결제 연출이 "카드 안내 → 승인 중 → 완료" 순서로 나온다
- [ ] 완료 화면에 주문번호·주문 내역·합계가 보인다
- [ ] 주문할 때마다 주문번호가 1씩 증가한다
- [ ] 실제 결제(카드 정보 입력 등)는 어디에도 없다

## 한계 발견하기
지금 주문번호와 주문 기록은 **이 폰(브라우저) 안에만** 있어요. 그래서:
- 태블릿을 바꾸면 주문번호가 처음부터 다시 시작되고
- 사장님이 매출을 **어디서도 볼 수 없어요**
→ 다음 단계에서 주문을 **DB(구글 시트)** 로 보냅니다.

## 배운 것
- 결제 = "요청 → 승인 → 완료" 순서의 흐름 (창업/결제 개념)
- 가상 연출로도 사용자 경험은 충분히 설계할 수 있다
- 기록이 기기 안에만 있으면 집계가 불가능 → DB의 필요성
