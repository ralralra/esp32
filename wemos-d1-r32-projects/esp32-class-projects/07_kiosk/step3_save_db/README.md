# 3단계 — 주문을 DB(구글 시트)에 저장

## 목표
결제(연출)가 끝나면 주문 내역이 **DB(구글 시트 '주문로그')** 에 한 줄씩 쌓인다.
주문번호도 이제 **서버(DB)가 발급** — 어느 태블릿에서 주문해도 번호가 이어진다.

## 핵심 아이디어 — 기록은 서버가 책임진다
```
앱: "이 주문 저장해줘"  →  fetch(URL + "?action=order&items=아메리카노(핫):1500&total=1500")
DB(Apps Script): 주문번호 발급 → 주문로그에 1줄 저장 → 주문번호 회신
앱: 받은 주문번호를 완료 화면에 크게 표시
```
이게 진짜 주문 시스템의 구조예요 — **화면은 앱이, 기록은 서버(DB)가.**
4회차에서 배운 "웹앱 ↔ Apps Script ↔ 시트" 뼈대를 그대로 재사용합니다.

## 해보기
1. [`docs/setup.md`](../docs/setup.md) 대로 시트(`주문로그` 탭) 만들기
2. [`kiosk_db.gs`](kiosk_db.gs) 를 Apps Script에 붙여넣고 **웹 앱으로 배포** → URL 복사
3. 브라우저 주소창으로 서버 먼저 테스트:
   `배포URL?action=order&items=테스트(핫):1000&total=1000` → 시트에 줄이 생기면 성공!
4. [`프롬프트.md`](프롬프트.md) 의 연결 지시(+ 복사한 URL)를 AI Studio에 붙여넣기
5. 앱에서 주문 → 시트에 새 줄이 쌓이고, 완료 화면 주문번호가 시트와 같은지 확인
6. **다른 폰/태블릿**에서도 주문해보기 → 주문번호가 이어짐 (공유!)

## 확인 ✅
- [ ] 주문할 때마다 시트 주문로그에 한 줄씩 쌓인다 (시각·주문번호·내역·합계)
- [ ] 완료 화면의 주문번호 = 시트의 주문번호
- [ ] 다른 기기에서 주문해도 번호가 이어진다
- [ ] 앱을 새로고침해도 기록은 시트에 그대로 남아 있다

## 배운 것
- 매출 데이터를 DB(시트)에 저장하면 여러 기기가 공유하고, 영원히 남는다
- 장바구니를 `이름(옵션):가격|...` 문자열로 보내고 서버가 저장하는 방법
- 출석·매점에서 배운 "저장은 한곳에서" 개념이 결제 기록에도 그대로
