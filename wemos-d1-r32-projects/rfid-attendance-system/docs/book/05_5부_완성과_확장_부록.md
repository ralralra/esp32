# 17장 전체 점검과 문제 해결

## 17.1 다섯 단계 점검 순서

모든 부품이 갖춰졌습니다. 이제 처음부터 끝까지 한 번 통과시켜 봅시다. **순서를 지키는 것이 중요합니다** — 각 단계는 그 아래 층이 정상임을 확인한 뒤에 그 위를 확인하는 구조이기 때문입니다.

**① 서버가 살아 있는가**
브라우저에서 `배포URL?action=periods`를 엽니다. 교시 목록 JSON이 나오고, 구글 시트에 세 탭이 생겨 있어야 합니다.

**② 리더기가 카드를 읽는가**
`uid_test`를 업로드하고 시리얼 모니터(115200)에서 학생증 UID를 확인합니다.

**③ 등록이 되는가**
앱의 [학생 관리]에서 학생 정보를 넣고 등록 시작 → 장치 LED가 **빠르게** 깜빡 → 태그 → 학생명단 시트에 줄이 생겼는지 확인.

**④ 출석이 되는가**
앱의 [출석체크]에서 시작 → LED가 **느리게** 깜빡 → 태그 → 앱에 결과 표시 + 출석기록 시트에 줄 확인.

**⑤ 하드웨어 없이도 되는가**
브라우저에서 `배포URL?action=tag&device=DEV001&uid=등록한UID`를 열어 태그를 흉내 내 봅니다. 앱의 시뮬레이션 버튼과 같은 동작입니다.

## 17.2 층별로 나누어 진단하기

문제가 생겼을 때 가장 나쁜 대응은 **모든 것을 한꺼번에 의심하는 것**입니다. 우리 시스템은 층이 뚜렷하므로 아래에서 위로 하나씩 확인하면 됩니다.

```
[층 4] 앱          ← 브라우저 개발자 도구, 시뮬레이션 버튼으로 확인
[층 3] 서버        ← 브라우저 주소창으로 직접 호출해 확인
[층 2] 장치 통신    ← 시리얼 모니터의 폴링 로그로 확인
[층 1] 리더기·배선  ← 버전 레지스터, uid_test로 확인
```

**진단의 핵심 질문은 하나입니다: "어느 층까지는 정상인가?"**

예를 들어 "앱에서 출석체크를 해도 반응이 없다"면 이렇게 좁혀 갑니다.

1. 브라우저에서 `action=periods`가 되는가? → 안 되면 **층 3(서버)** 문제
2. `action=start` 후 `action=poll`이 `ATTEND`를 주는가? → 안 되면 **층 3**
3. 시리얼 모니터에 "모드 변경: IDLE → ATTEND"가 뜨는가? → 안 뜨면 **층 2(장치 통신)**
4. LED는 깜빡이는데 태그가 안 잡히는가? → **층 1(리더기)**
5. 태그는 되는데 앱에 결과가 안 뜨는가? → **층 4(앱)**

이 습관은 이 프로젝트에서만 쓰는 것이 아닙니다. **복잡한 시스템을 다루는 사람이 갖춰야 할 가장 중요한 역량**이고, 이 수업이 기르려는 것도 결국 이것입니다.

## 17.3 자주 겪는 문제와 해법

### 하드웨어

**리더기 버전이 0x00 또는 0xFF로 나온다**
배선 오류입니다. 3V3(전원), IO05(SDA/SS), IO27(RST) 세 곳을 먼저 확인하세요. 특히 RC522의 SDA를 보드의 SDA 핀에 꽂았는지 확인하세요(5.3절).

**샘플 카드는 되는데 학생증만 안 된다**
6.4절의 순서대로: 최신 펌웨어(부스트+WUPA) 확인 → 카드 가장자리를 안테나 중앙에 밀착 → 폰으로 NfcA 여부 확인 → 전원 점검. 그래도 안 되면 PN532 모듈 교체를 검토하세요.

**인식 거리가 너무 짧다**
정상입니다. RC522의 인식 거리는 1~2cm입니다. "대는" 것이 아니라 "올려놓는" 것이라고 안내하세요.

### 네트워크

**와이파이 접속에서 점만 계속 찍힌다**
① 비밀번호 오타 ② 5GHz 전용 SSID(ESP32는 2.4GHz만) ③ 로그인 페이지가 뜨는 와이파이(ESP32는 로그인 불가). 폰 핫스팟을 대안으로 준비해 두세요.

**접속은 되는데 서버 응답이 비어 있다**
`httpGet()`에 `setFollowRedirects` 줄이 있는지 확인하세요(15.4절). 이 줄이 없으면 응답이 항상 빕니다. 그리고 `RELAY_URL`이 `/exec`으로 끝나는지 확인하세요.

### 서버

**앱에서 결과가 오지 않는다**
① 배포 액세스 권한이 "모든 사용자"인지 ② 코드 수정 후 **새 버전으로 재배포**했는지(9.4절) ③ 앱과 펌웨어의 `DEVICE_ID`가 정확히 같은지.

**태그했는데 UNKNOWN이 나온다**
그 카드가 학생명단에 없습니다. 시트를 열어 UID를 확인하세요. 대소문자나 앞의 0이 다르면 다른 번호로 취급됩니다.

**시각이 이상하게 기록된다**
Apps Script 프로젝트의 시간대 설정을 확인하세요. 코드는 `Asia/Seoul`을 명시하고 있지만, 시트 자체의 시간대가 다르면 표시가 어긋날 수 있습니다.

### 동작

**세션 중에 태그 반응이 둔하다**
정상입니다. 5초마다 서버에 폴링하는 동안 잠시 멈춥니다(14장). 카드를 떼지 말고 붙이고 있으면 반드시 잡힙니다.

**LED가 깜빡이지 않고 켜져만 있다**
최신 펌웨어인지 확인하세요. 14.1절에서 다룬 문제로, 폴링 순서를 바꾼 버전에서 해결되었습니다.

**컴파일 오류: redefinition of 'void setup()'**
새 스케치의 빈 틀 위에 붙여넣은 것입니다. 전체 선택(Ctrl+A) → 삭제 → 붙여넣기 하세요(13.3절).

# 18장 더 나아가기

여기까지 만들었다면, 이제 이 시스템은 여러분의 것입니다. 확장할 방향을 몇 가지 제안합니다. 모두 지금 구조 위에 얹을 수 있는 것들이라 팀 프로젝트 주제로도 좋습니다.

## 18.1 리더기를 여러 대로 늘리기

**난이도: 쉬움**

펌웨어의 `DEVICE_ID`를 `DEV002`, `DEV003`으로 바꾸고 각 교실에 설치하면 끝입니다. 세션이 리더기 이름을 열쇠로 저장되므로(11.4절) 서버 코드는 손댈 필요가 없습니다.

앱에서 리더기를 고르는 화면만 추가하면 됩니다. 시트의 '출석기록'에는 이미 리더기 열이 있어서, 어느 교실에서 태그했는지도 남습니다.

**생각해 볼 점:** 한 학생이 두 교실에서 동시에 태그되면 어떻게 될까요? 지금 코드는 각 교실에 하나씩 기록합니다. 막아야 할까요, 그대로 두어야 할까요?

## 18.2 등교와 하교를 함께 기록하기

**난이도: 보통**

세션의 `mode`에 `'leave'`를 추가하고, 출석기록에 구분 열을 하나 더하면 등·하교 관리 시스템이 됩니다.

바꿔야 할 곳:
- `startSession()` — `mode` 검증에 `leave` 추가
- `devicePoll()` — `LEAVE` 응답 추가 (LED 패턴도 하나 더)
- `doAttend()` — 하교 모드일 때는 지각 판정 대신 등교 기록이 있는지 확인

**생각해 볼 점:** 등교 기록 없이 하교만 찍힌 경우를 어떻게 처리해야 할까요?

## 18.3 통계 화면과 알림 붙이기

**난이도: 보통~어려움**

**통계 화면**: 앱에 이미 있는 `records` API로 데이터를 받아 주간·월간 출석률 그래프를 그립니다. 데이터 분석 수업과 자연스럽게 연결됩니다.

**알림 연동**: Apps Script에는 메일을 보내는 `MailApp` 기능이 있습니다. `doAttend()`에서 지각으로 판정될 때 보호자에게 메일을 보내도록 몇 줄만 추가하면 됩니다.

```javascript
if (status === '지각') {
  MailApp.sendEmail(보호자메일, '지각 알림',
    student.name + ' 학생이 ' + time + '에 등교했습니다.');
}
```

**생각해 볼 점:** 이 기능은 기술적으로는 쉽지만, 윤리적으로는 신중해야 합니다. 누구에게, 언제, 어떤 내용을 보낼지 정하는 일에는 학생·보호자의 동의와 학교의 방침이 필요합니다. **"할 수 있다"와 "해도 된다"는 다르다** — 서비스 기획 토론으로 이어가기 좋은 주제입니다.

## 18.4 개인정보를 다루는 사람의 책임

이 시스템을 실제로 운영한다면 반드시 지켜야 할 것들이 있습니다.

**시트 공유 범위를 최소로 두세요.** 학생명단에는 이름과 학년·반·번호가 들어 있습니다. UID 자체는 카드 번호에 불과하지만, 이름과 묶이는 순간 개인정보가 됩니다. 링크를 아는 사람 모두가 볼 수 있는 설정은 피하세요.

**필요 이상으로 모으지 마세요.** 번호가 꼭 필요한가요? 학년·반만으로 충분하지 않나요? **수집하지 않은 정보는 유출될 수 없습니다** — 개인정보 보호의 가장 확실한 방법입니다.

**보관 기간을 정하세요.** 학기가 끝난 출석기록을 언제까지 둘지 미리 정해 두세요.

**동의를 받으세요.** 학생증을 등록한다는 것은 그 학생의 카드 번호를 저장한다는 뜻입니다. 무엇을 왜 저장하는지 알리고 동의를 받는 것이 원칙입니다.

**법적 출결 대장으로 쓰지 마세요.** 이 시스템은 교육용·보조용입니다. 태그 실패나 장치 고장이 학생에게 불이익이 되어서는 안 됩니다.

> **💡 수업 마무리 활동**
> 마지막 차시에 이 주제로 토론해 보세요. "우리가 만든 시스템은 어떤 정보를 모으는가? 그 정보로 무엇을 할 수 있는가? 하면 안 되는 일은 무엇인가?" 기술을 만들 줄 아는 사람이 그 기술의 영향을 생각하는 연습 — 이것이 이 프로젝트의 마지막 학습 목표입니다.

### 마치며

첫 장에서 본 세 장면을 기억하시나요? 버튼을 누르면 불이 깜빡이고, 카드를 대면 소리가 나고, 화면에 이름이 뜨는 것.

이제 그 안에서 무슨 일이 벌어지는지 모두 아실 겁니다. 전파가 카드의 코일에 전기를 만들고, 칩이 깨어나 번호를 답하고, 그 번호가 와이파이를 타고 구글의 서버로 가고, 서버가 표를 뒤져 이름을 찾고, 시각을 비교해 지각을 판정하고, 시트에 한 줄을 쓰고, 1초마다 묻고 있던 앱이 그 결과를 받아 화면에 그립니다.

이 모든 것이 여러분이 만든 것입니다.

그리고 이 구조는 출석 시스템에만 쓰이는 것이 아닙니다. 도서 대출, 실험실 출입, 물품 관리, 무인 매장 — 카드를 대는 모든 시스템이 같은 뼈대를 씁니다. 여러분은 이제 그 뼈대를 손으로 만들어 본 사람입니다. 다음에 무엇을 만들지는 여러분에게 달려 있습니다.

# 부록

## A. 통신 규칙 전체 목록

### ESP32 ↔ 서버 (한 줄 텍스트)

| 요청 | 응답 | 뜻 |
|---|---|---|
| `?action=poll&device=` | `IDLE` | 할 일 없음 (대기) |
| | `ATTEND` | 출석 세션 진행 중 |
| | `REGISTER` | 등록 세션 진행 중 |
| `?action=tag&device=&uid=` | `OK,이름,상태,시각` | 출석 기록 완료 → 삑삑 |
| | `OK_REG,이름` | 학생증 등록 완료 → 삑삑 |
| | `UNKNOWN` | 미등록 카드 → 삐— |
| | `DUP,이름` | 이미 등록된 카드(등록 모드) → 삐— |
| | `MISMATCH,이름` | 대상이 아닌 학생의 카드 → 삐— |
| | `ALREADY,이름,시각` | 이미 이번 교시에 출석 → 삐— |
| | `IDLE` | 세션이 끝났거나 만료됨 |

### 앱 ↔ 서버 (JSON)

| action | 파라미터 | 응답 |
|---|---|---|
| `start` | `mode`(attend/register), `device`, `period`, `name`, `grade`, `klass`, `number`, `lateAfter`, `timeout` | `{ok, timeout, lateAfter}` |
| `status` | `device` | `{state, mode, result}` |
| `cancel` | `device` | `{ok}` |
| `students` | — | `{ok, students:[{uid,name,grade,klass,number,registeredAt}]}` |
| `records` | `date`, `period` | `{ok, date, records:[{date,time,period,uid,name,status,device}]}` |
| `periods` | — | `{ok, periods:[{period,start,lateAfter}]}` |

**status의 state 값**

| state | 뜻 | 앱의 화면 |
|---|---|---|
| `none` | 세션 없음(만료/취소) | 시간 초과 |
| `waiting` | 태그 대기 중 | 카운트다운 |
| `done` | 처리 완료 | 결과 표시 |

**result의 내용**

| 필드 | 성공 시 | 실패 시 |
|---|---|---|
| `ok` | `true` | `false` |
| `name` | 학생 이름 | (해당되면) 학생 이름 |
| `status` | `출석` / `지각` | — |
| `time` | `HH:mm:ss` | (ALREADY면 기존 시각) |
| `reason` | — | `unknown` / `mismatch` / `dup` / `already` |

## D. 용어 사전

| 용어 | 뜻 |
|---|---|
| **RFID** | 전파로 정보를 읽는 기술. 우리는 13.56MHz 대역을 씁니다 |
| **NFC** | RFID 중 가까운 거리(수 cm)에서 쓰는 규격. 폰에 들어 있는 그것 |
| **UID** | 카드의 고유번호. 예: `6F3178D9` |
| **ISO 14443 Type A** | RC522가 읽을 수 있는 카드 규격. 폰 앱에서 `NfcA`로 표시됨 |
| **SPI** | 부품끼리 데이터를 주고받는 통신 방식. SCK·MOSI·MISO·SS 사용 |
| **GPIO** | 마이크로컨트롤러의 입출력 핀 번호 |
| **세션** | "지금 카드를 기다리는 중"이라는 서버의 메모. 30초 뒤 자동 소멸 |
| **폴링** | 주기적으로 "할 일 있나요?"라고 물어보는 통신 방식 |
| **캐시(Cache)** | 정해진 시간 동안만 값을 보관하는 임시 저장소 |
| **JSON** | 데이터를 주고받는 표준 문자 형식. `{"이름":"값"}` 모양 |
| **GET 요청** | 주소에 값을 붙여 보내는 가장 단순한 웹 요청 방식 |
| **CORS** | 브라우저가 다른 서버로 요청할 때 하는 보안 검문 |
| **리다이렉트** | 서버가 "다른 주소로 가세요"라고 안내하는 응답 |
| **블로킹** | 어떤 작업이 끝날 때까지 다른 일을 못 하고 멈춰 있는 상태 |
| **WUPA / REQA** | 카드를 찾는 두 가지 신호. WUPA는 잠든 카드까지 깨움 |
| **Apps Script** | 구글 시트에 붙여 쓰는 자바스크립트 실행 환경 |
| **제로 패딩** | 자릿수를 맞추려고 앞에 0을 채우는 것. `F` → `0F` |
