## 4.2 소프트웨어 환경 갖추기

**① Arduino IDE와 ESP32 보드 패키지**

Arduino IDE를 설치한 뒤, ESP32 보드를 쓸 수 있게 보드 패키지를 추가해야 합니다. `파일 → 환경설정 → 추가 보드 관리자 URL`에 ESP32 패키지 주소를 넣고, `툴 → 보드 → 보드 관리자`에서 "esp32"를 검색해 설치합니다.

설치가 끝나면 `툴 → 보드 → esp32 → **ESP32 Dev Module**`을 선택합니다. 목록에 `WEMOS D1 R32`가 보이면 그것을 골라도 됩니다 — 둘 다 동일하게 동작합니다.

**② MFRC522 라이브러리**

`툴 → 라이브러리 관리`에서 **MFRC522**를 검색해 설치합니다(제작자: GithubCommunity). 이 라이브러리가 RC522와 대화하는 어려운 부분을 대신해 줍니다.

**③ 포트 선택**

`툴 → 포트`에서 보드가 연결된 포트를 고릅니다. 어느 것인지 모르겠다면 이렇게 하세요. **케이블을 뽑고 목록을 확인 → 다시 꽂고 목록을 확인 → 새로 생긴 것**이 여러분의 보드입니다.

**④ 구글 계정과 와이파이**

구글 시트와 Apps Script를 쓸 계정이 필요합니다. 그리고 **2.4GHz 와이파이**가 있어야 합니다. 이것은 뒤에서 다시 강조하겠습니다.

## 4.3 수업 전 반드시 확인할 세 가지

교사용으로 이 책을 보신다면, 수업 전에 직접 확인해야 할 것이 셋 있습니다. 현장에서 발목을 잡는 것은 거의 항상 이 셋입니다.

**① 학교 와이파이가 2.4GHz인가?**

ESP32는 **2.4GHz만** 지원합니다. 5GHz 전용 SSID에는 접속할 수 없습니다. 요즘 공유기는 대개 두 대역을 모두 쓰지만, SSID가 `학교와이파이_5G`처럼 분리되어 있다면 2.4GHz 쪽 이름으로 접속해야 합니다.

더 까다로운 경우가 있습니다. 접속하면 로그인 페이지가 뜨는 방식(캡티브 포털)의 와이파이는 ESP32가 로그인할 수 없어 못 씁니다. **이럴 때를 대비해 스마트폰 핫스팟을 준비**해 두세요. 핫스팟은 대개 2.4GHz이고 로그인도 없어서 잘 됩니다.

**② 학생증이 Type A인가?**

2.3절에서 다룬 대로, 학생증을 폰의 NFC Tools로 스캔해 `NfcA`가 있는지 미리 확인하세요. 아니라면 수업 계획을 바꿔야 합니다(PN532 모듈로 교체하거나, 별도의 카드/스티커 태그를 나눠주는 방식).

**③ USB 케이블이 데이터 케이블인가?**

충전만 되는 케이블이 섞여 있으면 "포트가 안 보인다"는 문제로 20분을 날립니다. 미리 한 개씩 꽂아 보고 확인하세요.

# 5장 배선 — 리더기를 보드에 연결하기

## 5.1 SPI 통신과 여섯 개의 선

RC522와 ESP32는 **SPI**라는 방식으로 대화합니다. 전선 네 가닥으로 데이터를 주고받는 통신 규약인데, 각 선의 역할이 분명합니다.

| 선 | 이름의 뜻 | 하는 일 |
|---|---|---|
| **SCK** | Serial Clock | 박자를 맞추는 신호. "지금이야, 지금이야" 하고 계속 신호를 보냅니다 |
| **MOSI** | Master Out, Slave In | 보드 → 모듈 방향의 데이터 선 |
| **MISO** | Master In, Slave Out | 모듈 → 보드 방향의 데이터 선 |
| **SS(SDA)** | Slave Select | "지금부터 너에게 말하는 거야"라고 상대를 지목하는 선 |

여기에 **RST**(리셋)와 **전원 두 가닥**(3.3V, GND)을 더하면 일곱 개입니다. RC522에는 `IRQ`라는 핀도 있지만 우리는 쓰지 않습니다.

> **📌 왜 SS 핀이 필요할까?**
> SPI는 여러 부품을 같은 세 선(SCK·MOSI·MISO)에 나란히 붙일 수 있게 설계되었습니다. 그러면 "지금 말하는 상대가 누구냐"를 구분할 방법이 필요한데, 그것이 SS 핀입니다. 각 부품마다 SS 선을 따로 두고, 말을 걸 상대의 SS만 켜는 식입니다. 교실에서 여러 명이 있을 때 이름을 부르고 말하는 것과 같습니다.

## 5.2 배선표와 배선도

**Wemos D1 R32 기준** (핀에 GPIO 번호가 인쇄된 보드)

|---|---|---|
| **3.3V** | **3V3** | 위쪽 전원 헤더 |
| **RST** | **IO27** | 아래쪽 디지털 헤더 |
| **GND** | **GND** | 아무 GND나 |

| **MISO** | **IO19** | 아래쪽 디지털 헤더 |
| **MOSI** | **IO23** | 아래쪽 디지털 헤더 |
| **SCK** | **IO18** | 아래쪽 디지털 헤더 |
| **SDA(SS)** | **IO05** | 아래쪽 디지털 헤더 |

## 5.3 가장 많이 틀리는 두 곳

배선 실수는 대부분 이 두 곳에서 납니다. 칠판에 크게 적어 두세요.

### ⚠ 첫째 — 전원은 반드시 3.3V

**RC522를 5V에 연결하면 모듈이 고장 납니다.** 보드에는 `5V`와 `VIN` 핀이 나란히 있어서 잘못 꽂기 쉽습니다. 반드시 **`3V3`** 이라고 적힌 핀에 꽂으세요.

한 번 태운 모듈은 되살릴 수 없으므로, 전원을 켜기 **전에** 팀끼리 서로의 배선을 교차 검사하는 습관을 들이면 사고를 크게 줄일 수 있습니다.

### ⚠ 둘째 — 이름이 같다고 그 자리가 아닙니다

Wemos D1 R32 보드의 오른쪽 아래에는 `GND · RST · SDA · SCL`이라고 인쇄된 핀들이 있습니다. 여기에 함정이 둘 있습니다.

**RC522의 SDA를 보드의 SDA에 꽂으면 안 됩니다.** 보드의 SDA는 I2C라는 **다른 통신 방식**을 위한 핀(GPIO21)입니다. RC522의 SDA는 사실 SS(Slave Select)의 다른 이름이며, **IO05**에 꽂아야 합니다. 이름이 같아서 실수하기 딱 좋은 곳입니다.

**RC522의 RST도 보드의 RST에 꽂으면 안 됩니다.** 보드의 RST는 보드 자체를 재시작하는 핀입니다. RC522의 RST는 **IO27**에 꽂습니다.

## 5.4 배선이 맞는지 확인하는 법

배선을 마쳤으면 눈으로만 확인하지 말고 **장치에게 직접 물어봅시다.** 다음 장에서 만들 `uid_test` 코드를 올리고 시리얼 모니터를 열면 이런 줄이 뜹니다.

```
RC522 버전 레지스터: 0x92
✅ 리더기 연결 OK. 학생증을 대보세요.
```

- **`0x92`나 `0x91`, `0x12` 같은 값**이 나오면 → 배선 정상, SPI 통신 성공
- **`0x00` 또는 `0xFF`** 가 나오면 → 배선 오류. 3V3, IO05, IO27 세 곳을 다시 확인

`0x92`라는 숫자 자체에 큰 의미는 없습니다. 리더기 칩의 버전 번호일 뿐입니다. 중요한 것은 **"0x00도 0xFF도 아니면 성공"** 이라는 점입니다. 이 두 값은 "아무도 대답하지 않았다"는 뜻이기 때문입니다.

### 5장 정리

- SPI는 SCK(박자)·MOSI(보내기)·MISO(받기)·SS(상대 지목) 네 선으로 통신합니다.
- 전원은 반드시 3.3V. 5V는 모듈을 태웁니다.
- RC522의 SDA는 보드의 SDA가 아니라 IO05, RC522의 RST는 보드의 RST가 아니라 IO27.
- 배선 검사는 버전 레지스터 값으로 합니다.

# 6장 첫 코드 — 학생증 번호 읽기

이제 첫 코드를 올립니다. 와이파이도 서버도 필요 없습니다. 목표는 하나 — **내 학생증의 번호를 눈으로 보는 것**입니다.

> 전체 코드: `github.com/ralralra/esp32/blob/main/wemos-d1-r32-projects/rfid-attendance-system/firmware/uid_test/uid_test.ino`

## 6.1 setup() — 리더기에게 이름을 물어보다

```cpp
#include <SPI.h>
#include <MFRC522.h>

#define PIN_SS   5    // RC522 SDA(SS)
#define PIN_RST  27   // RC522 RST

MFRC522 rfid(PIN_SS, PIN_RST);

void setup() {
  Serial.begin(115200);
  SPI.begin();          // SCK=18, MISO=19, MOSI=23 (ESP32 기본 SPI 핀)
  rfid.PCD_Init();
  delay(100);
  ...
}
```

한 줄씩 봅시다.

`#define PIN_SS 5`는 "앞으로 `PIN_SS`라고 쓰면 5를 뜻한다"는 이름표입니다. 숫자 5를 코드 여기저기에 흩어 놓는 대신 이름을 붙여 두면, 나중에 핀을 바꿀 때 이 한 줄만 고치면 됩니다.

`MFRC522 rfid(PIN_SS, PIN_RST);`는 리더기를 다룰 **객체**를 만드는 줄입니다. 앞으로 `rfid.무엇()` 형태로 리더기에게 일을 시킵니다.

`Serial.begin(115200)`은 컴퓨터와 대화할 통로를 여는 것입니다. 115200은 통신 속도인데, 시리얼 모니터에서도 같은 숫자를 골라야 글자가 깨지지 않습니다.

`SPI.begin()`이 흥미롭습니다. **SCK·MISO·MOSI 핀 번호를 어디에도 적지 않았는데** 통신이 됩니다. ESP32에는 SPI용으로 정해진 기본 핀(18·19·23)이 있어서, 그 자리에 꽂았다면 라이브러리가 알아서 씁니다. 우리 배선표가 그 번호를 쓴 이유입니다.

`rfid.PCD_Init()`은 리더기를 깨워 초기 설정을 하는 명령입니다.

이어서 자가진단 부분입니다.

```cpp
  // 리더기가 응답하는지 자가진단
  byte version = rfid.PCD_ReadRegister(MFRC522::VersionReg);
  Serial.print("RC522 버전 레지스터: 0x");
  Serial.println(version, HEX);

  if (version == 0x00 || version == 0xFF) {
    Serial.println("⚠️ 리더기 응답 없음! 배선을 다시 확인하세요");
  } else {
    Serial.println("✅ 리더기 연결 OK. 학생증을 대보세요.");
  }
```

`PCD_ReadRegister(VersionReg)`는 리더기 안의 '버전 번호가 적힌 서랍'을 열어 보는 명령입니다. 대답이 오면 배선이 맞은 것이고, `0x00`이나 `0xFF`가 오면 아무도 없는 곳에 대고 물어본 것입니다.

**컴퓨터가 부품에게 "너 이름이 뭐야?"라고 물어보는 것** — 자가진단의 개념을 이렇게 설명하면 학생들이 쉽게 받아들입니다. 그리고 이 습관은 앞으로 어떤 부품을 다루든 유용합니다. "일단 대화가 되는지부터 확인한다"는 것이 하드웨어 디버깅의 첫걸음이기 때문입니다.

## 6.2 감도와 출력을 최대로 올리는 이유

`PCD_Init()` 바로 다음에 세 줄이 더 있습니다. 이 세 줄에는 사연이 있습니다.

```cpp
  // 안테나 감도를 최대로 (기본값은 중간)
  rfid.PCD_SetAntennaGain(MFRC522::RxGain_max);

  // 송신 출력 부스트 — 안테나가 작은 카드도 깨울 수 있게
  rfid.PCD_WriteRegister(MFRC522::GsNReg, 0xF8);    // 기본 0x88
  rfid.PCD_WriteRegister(MFRC522::CWGsPReg, 0x3F);  // 기본 0x20
```

**처음에는 이 세 줄이 없었습니다.** 배선을 마치고 자가진단도 통과했는데, 카드를 대도 아무 반응이 없었습니다. 문제를 하나씩 좁혀 나간 과정은 이랬습니다.

**1단계 — 수신 감도(`PCD_SetAntennaGain`)**
RC522의 기본 수신 감도는 중간값입니다. 특히 저가 클론 모듈은 이 설정 없이는 인식 거리가 1cm도 안 나오는 경우가 많습니다. 최대로 올렸더니 샘플 카드가 읽히기 시작했습니다.

**2단계 — 카드마다 다른 결과**
그런데 이상한 일이 벌어졌습니다. 토스뱅크 카드, 교통카드, 키트에 들어 있던 샘플 카드는 잘 읽히는데 **학생증과 유스카드만 전혀 읽히지 않았습니다.** 폰의 NFC로는 다섯 장 모두 읽혔고, 전부 `NfcA` 방식이었습니다. 카드 종류의 문제가 아니었던 것입니다.

**3단계 — 송신 출력(`GsNReg`, `CWGsPReg`)**
남은 가능성은 전력이었습니다. 2장에서 본 대로 카드는 리더기가 보내는 전파에서 전기를 얻습니다. 안테나 코일이 작거나 결합이 나쁜 카드는 같은 전파에서 얻는 전기가 적어, 칩이 깨어날 만큼 모이지 않습니다. 폰은 전파 출력이 훨씬 세서 다 읽혔던 것이고요.

그래서 RC522의 반송파 구동 세기를 조절하는 두 레지스터를 최대치로 올렸습니다. `GsNReg`의 상위 4비트가 반송파 세기라 `0x88`을 `0xF8`로, `CWGsPReg`는 `0x20`을 `0x3F`로 바꿨습니다.

**결과: 학생증이 읽혔습니다.**

> **📌 이 과정이 알려 주는 것**
> 데이터시트를 뒤져 레지스터 값을 바꾸는 일은 어렵게 들리지만, 그 앞의 사고 과정은 단순합니다. **되는 것과 안 되는 것을 나열하고, 공통점과 차이점을 찾고, 남은 가설을 하나씩 시험하는 것.** 학생들에게 가르칠 것은 `0xF8`이라는 숫자가 아니라 이 절차입니다. 수업에서는 일부러 이 세 줄을 주석 처리해 학생증이 안 읽히는 상황을 만들고, 함께 원인을 추론해 보는 활동도 좋습니다.

## 6.3 loop() — UID를 문자열로 바꾸기

```cpp
void loop() {
  // 새 카드가 올라왔고, UID를 읽을 수 있으면
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) {
    delay(50);
    return;
  }

  // UID를 "6F3178D9" 처럼 대문자 16진수 문자열로 만든다
  String uid = "";
  for (byte i = 0; i < rfid.uid.size; i++) {
    if (rfid.uid.uidByte[i] < 0x10) uid += "0";
    uid += String(rfid.uid.uidByte[i], HEX);
  }
  uid.toUpperCase();

  Serial.print("카드 인식! UID = ");
  Serial.println(uid);

  rfid.PICC_HaltA();        // 카드와의 통신 종료
  rfid.PCD_StopCrypto1();
  delay(1000);              // 같은 카드 연속 인식 방지
}
```

**첫 부분 — 카드가 있는지 확인**

`PICC_IsNewCardPresent()`는 "새 카드가 왔나?"를, `PICC_ReadCardSerial()`은 "그 카드의 번호를 읽을 수 있나?"를 확인합니다. 둘 중 하나라도 실패하면 잠깐 쉬고 `return`으로 이번 회차를 끝냅니다. `loop()`는 계속 반복되므로 곧 다시 확인합니다.

**둘째 부분 — 바이트를 글자로**

읽은 UID는 `rfid.uid.uidByte[]`라는 배열에 숫자로 들어 있습니다. 예를 들어 `[111, 49, 120, 217]`처럼요. 이것을 사람이 읽고 시트에 저장할 수 있는 `"6F3178D9"` 형태로 바꾸는 것이 이 반복문입니다.

`String(값, HEX)`가 숫자를 16진수 글자로 바꿔 줍니다. 그런데 여기 함정이 하나 있어서 앞에 조건문이 붙어 있습니다.

```cpp
    if (rfid.uid.uidByte[i] < 0x10) uid += "0";
```

**질문: 왜 16보다 작으면 "0"을 먼저 붙일까요?**

16진수로 한 자리인 값들(0~15) 때문입니다. 예를 들어 값이 15라면 `String(15, HEX)`는 `"F"` 한 글자를 내놓습니다. 그러면 `6F` `31` `78` `F`가 이어져 `6F3178F`라는 일곱 글자가 되고, 원래 번호가 무엇이었는지 알 수 없게 됩니다. 그래서 한 자리짜리 앞에 `0`을 붙여 `0F`로 만들어 **항상 두 자리를 유지**하는 것입니다.

이런 처리를 **제로 패딩**이라고 하며, 시각을 `9:5`가 아니라 `09:05`로 쓰는 것과 같은 이치입니다. 짧은 퀴즈로 내기 좋은 부분입니다.

`uid.toUpperCase()`로 대문자로 통일하는 이유도 같습니다. `6f3178d9`와 `6F3178D9`를 다른 번호로 착각하지 않기 위해서입니다. 서버 쪽 코드에서도 같은 이유로 대문자로 바꿉니다.

**셋째 부분 — 마무리**

`PICC_HaltA()`는 방금 읽은 카드에게 "이제 조용히 있어"라고 말하는 명령입니다. 이렇게 재워 두지 않으면 같은 카드를 계속 다시 읽습니다. `delay(1000)`은 한 번 더 확실히 막는 장치입니다 — 카드를 1초 넘게 대고 있어도 한 번만 인식됩니다.

## 6.4 실습: 내 학생증의 번호는 무엇인가

코드를 올리고 시리얼 모니터(115200)를 엽니다.

```
RC522 버전 레지스터: 0x92
✅ 리더기 연결 OK. 학생증을 대보세요.
카드 인식! UID = 6F3178D9  (MIFARE 1KB)
```

이 번호를 적어 두세요. 4부에서 앱으로 등록할 때, 시트에 이 번호가 그대로 들어가는 것을 확인하게 됩니다.

### 카드가 안 읽힐 때

**리더기는 OK인데 카드가 안 읽힌다면:**

1. **밀착하고 기다리기** — 카드를 리더기 위에 올려놓고 2~3초 유지하세요. 스치듯 대면 안 됩니다.
2. **다른 카드로 교차 확인** — 교통카드 등 `NfcA`로 확인된 다른 카드를 대 보세요. 그것이 읽히면 리더기는 정상이고, 문제는 그 카드에 있습니다.
3. **스위트 스팟 찾기** — 스마트카드는 안테나 코일이 카드 **가장자리를 따라** 감겨 있는 경우가 많습니다. 카드 중앙이 아니라 **모서리 쪽이 리더기 안테나 한가운데에 오도록** 밀착한 채 천천히 위치를 옮겨 보세요. 뒤집어서도 시도해 보세요.
4. **부스트 확인** — 6.2절의 세 줄이 코드에 들어 있는지 확인하세요.
5. **전원 확인** — USB 허브 대신 PC에 직접, 짧은 케이블로 연결해 보세요. 3.3V 전원이 약하면 전파 출력도 약해집니다.

여기까지 해도 안 되면 RC522의 출력 한계입니다. **PN532 모듈**로 바꾸면 대개 해결됩니다(폰과 비슷한 수준의 출력에 Type A/B를 모두 지원). 또는 안 읽히는 학생에게만 별도의 태그를 나눠주는 방법도 현실적입니다.

### 6장 정리

- `setup()`에서 리더기를 초기화하고, 버전 레지스터를 읽어 배선을 자가진단합니다.
- 수신 감도 최대 + 송신 출력 부스트 세 줄이 학생증 인식의 핵심입니다.
- `loop()`에서 카드를 감지하고, 바이트 배열을 두 자리씩 16진수 문자열로 바꿉니다.
- 제로 패딩과 대문자 통일은 번호를 항상 같은 형식으로 유지하기 위한 처리입니다.
