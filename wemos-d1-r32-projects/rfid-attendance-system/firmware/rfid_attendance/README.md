# 완성 펌웨어 — 앱 연동 출석체크

앱에서 [출석체크 시작]을 누르면 LED가 깜빡이고, 학생증을 태그하면 앱에 결과가 뜹니다.

## 먼저 필요한 것

- [`uid_test`](../uid_test/) 로 배선·학생증 확인 완료
- [`../../apps_script/README.md`](../../apps_script/README.md) 로 중계서버 배포 완료 (URL 확보)

## 설정

`rfid_attendance.ino` 상단 [설정] 4줄만 수정:

```cpp
const char* WIFI_SSID  = "와이파이이름";       // 2.4GHz 와이파이만 가능!
const char* WIFI_PASS  = "와이파이비밀번호";
const char* RELAY_URL  = "https://script.google.com/macros/s/배포ID/exec";
const char* DEVICE_ID  = "DEV001";            // 앱과 같은 리더기 이름
```

## 동작 확인 (시리얼 모니터 115200)

1. `접속 완료! IP: ...` → 부저 삑삑
2. 앱(또는 브라우저)에서 세션 시작 → 2초 안에 `모드 변경: IDLE → ATTEND` + LED 깜빡
3. 학생증 태그 → `✅ 출석 확인! → OK,김세이프,출석,08:55:01` + 삑삑
4. 앱 결과 화면에 이름·시각·상태 표시

ESP32 없이 앱만 테스트하려면 브라우저에서
`중계서버URL?action=tag&device=DEV001&uid=등록된UID` 를 열면 태그를 흉내낼 수 있습니다.

## LED / 부저 신호 정리

LED는 보드 내장 파란 LED(GPIO2)와 외부 LED(GPIO16)가 항상 똑같이 동작합니다.
외부 LED는 긴 다리를 GPIO16, 짧은 다리를 저항(220Ω쯤) 거쳐 GND에 연결하세요. 안 달아도 동작합니다.

| 신호 | 뜻 |
|---|---|
| LED 꺼짐 | 대기 중 (세션 없음) |
| LED 천천히 깜빡 (0.5초) | 출석 세션 — 학생증을 태그하세요 |
| LED 빠르게 깜빡 (0.15초) | 등록 세션 — 새 학생증을 태그하세요 |
| LED 계속 켜짐 | 태그한 카드를 서버로 보내는 중 |
| 삑삑 (짧게 2번) | 성공 (출석 기록됨 / 등록됨) |
| 삐— (길게 1번) | 실패 — 시리얼 모니터에서 사유 확인 (미등록/중복/다른 학생 카드) |

## 자주 걸리는 것

- **와이파이 접속 안 됨**: ESP32는 **2.4GHz만** 지원. 5GHz 전용 SSID는 안 붙습니다.
- **폴링 응답이 이상함**: RELAY_URL이 `/exec`로 끝나는지, 배포 액세스가 "모든 사용자"인지 확인.
- **`HTTP 오류: -11`이 반복됨**: 읽기 시간 초과입니다. 연결은 됐지만 응답을 못 받은 것.
  부팅할 때 뜨는 **`── 중계서버 점검 ──`** 결과를 먼저 보세요.
  - `❌ 구글 로그인 페이지로 보내고 있습니다` → **가장 흔한 원인.**
    배포 관리에서 액세스 권한을 **"모든 사용자"** 로 바꾸고 **새 버전**으로 재배포하세요.
    (`Google 계정이 있는 모든 사용자`가 아니라 그냥 **모든 사용자**)
  - `⚠️ RELAY_URL이 /exec 으로 끝나지 않습니다` → `/dev` 주소는 로그인이 필요해 쓸 수 없습니다.
  - `✅ 서버 정상 응답`인데도 -11이 계속되면 → 회선 지연입니다.
    핫스팟 대신 일반 2.4GHz 와이파이를 쓰거나, 신호가 센 곳으로 옮겨 보세요.

  > 💡 **브라우저 테스트는 시크릿 창으로 하세요.** 일반 창은 이미 구글에 로그인되어 있어
  > 액세스 권한이 잘못돼 있어도 정상으로 보입니다. 시크릿 창에서 로그인 화면이 뜨면
  > 그것이 곧 ESP32가 겪는 상황입니다.
- **태그해도 반응 없음**: LED가 깜빡이는 상태(세션 중)에서만 태그가 전송됩니다.

## 카드 스캔이 통신 때문에 멈추지 않는 이유

서버 요청(HTTPS)은 한 번에 2~3초, 회선이 느리면 25초까지 걸립니다.
예전에는 그 시간 동안 카드 스캔이 통째로 멈춰서, 폴링 간격을 늘려 피하는 식이었어요.

지금은 **통신을 다른 코어에서 따로 돌립니다.**

| 코어 | 하는 일 |
|---|---|
| 코어 1 (`loop`) | 카드 스캔 · LED · 부저 — 멈추지 않음 |
| 코어 0 (`networkTask`) | 서버 폴링 · 태그 전송 — 오래 걸려도 무방 |

둘은 큐로만 주고받아서 변수를 같이 만지지 않습니다.
카드를 태그하면 즉시 LED가 켜지고(접수됨), 서버 결과가 오면 부저로 알려줍니다.
앞 카드를 보내는 중에 다음 카드를 대면 "잠시 후 다시 태그해주세요"가 나옵니다.
