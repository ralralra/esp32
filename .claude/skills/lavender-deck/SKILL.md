# Lavender Deck — 이 사용자의 기본 PPT 디자인

사용자가 참고 덱("4시간 뒤, 앱개발자 탄생")의 구성과 색감을 기본 디자인으로 정했다.
앞으로 만드는 모든 덱은 이 스킬의 `scripts/deck.js`로 만든다. 디자인을 새로 고르거나 묻지 않는다.
내용·구조(몇 장, 무슨 순서)는 요청에 맞게 짜되, 색·글꼴·배치·모티프는 여기 것만 쓴다.

왜 모듈을 쓰는가: 색과 배치를 손으로 다시 적으면 덱마다 조금씩 달라진다. 함수 하나로 모티프를 찍어내면
참고 덱과 같은 느낌이 자동으로 유지되고, 빌드 스크립트에는 내용만 남는다.

## 작업 순서

1. **내용부터 정한다.** 한 장에 한 메시지. 장마다 어떤 모티프가 맞는지 고른다 (아래 표).
   학생용·교사용처럼 시점이 정해지면 그 말투로, 교사가 볼 내용은 슬라이드가 아니라 **발표자 노트**(`notes`)에.
2. **빌드 폴더를 만든다** (스크래치패드 안). 의존 모듈이 없으면 그 폴더에서 한 번:
   `npm install pptxgenjs react-icons react react-dom sharp jszip`
3. **`assets/example_build.js`를 복사해 내용을 바꾼다.** `createDeck` → `d.slide({...})`로 장을 만들고 `d.step`, `d.card`, `d.codeBar`… 로 채운 뒤 `d.finish("out.pptx")`.
   `require` 경로는 이 스킬의 `scripts/deck.js` 절대 경로로.
4. **빌드 → 검사 → 렌더 → 눈으로 확인.** 겹침·넘침은 글을 줄이거나 상자를 키워서 고치고 다시 빌드한다.
   ```bash
   cd <빌드 폴더> && node build.js out.pptx
   python3 <pptx 스킬>/scripts/office/validate.py out.pptx          # "All validations PASSED!"
   python3 <pptx 스킬>/scripts/office/soffice.py --headless --convert-to pdf out.pptx
   pdftoppm -jpeg -r 70 out.pdf slide                                  # 장별 JPEG → 2×2 격자로 모아 Read
   ```
   렌더는 LibreOffice라 Noto Sans KR이 다른 글꼴로 바뀌어 보일 수 있다. 실제 PowerPoint에서는 글자가 조금 더 좁으니, 미리보기에서 살짝 끼는 정도는 두고 **겹침과 잘림만** 고친다.
5. 결과 파일을 사용자에게 보내고(SendUserFile), 저장소 작업이면 정해진 자리에 넣고 커밋한다.

## 장 구성 규칙 (참고 덱을 따른다)

- **표지**: `slide({cover: true})` — 왼쪽에 알약 태그 → 두 줄 제목(48pt, "N시간 뒤,\n○○ 탄생" 식 기대감) → 회보라 부제 → 아이콘 타일 4개. 오른쪽에 `phoneMock` 또는 사진 카드. 어두운 표지는 쓰지 않는다.
- **본문**: `slide({label, tag, title, sub})`. 라벨은 단원("① 배선", "시작 · 오늘의 지도"), 태그는 "따라 하기"(진남색) 또는 "실습 · 20분"(보라, `tagColor: d.H.accent1`). 제목은 **왼쪽 정렬** 30pt, 한 줄에 들어가게 (한글 기준 22자 안팎).
- **두 단**: 왼쪽 7.3in(그림·코드·표) + 오른쪽 4.45in(단계·증상 카드). 왼쪽 큰 것, 오른쪽 설명이 참고 덱의 기본 호흡이다.
- **맨 아래 한 줄**: 주의·도전·결론은 `callout`(연보라) 한 개. 강한 주의만 `banner`(주황). 한 장에 주황은 한 덩어리.
- **마무리**: 어두운 배경 대신 `numberCard` 나열 + 보라 `banner` 결론.
- 본문 글자 10pt 미만 금지, 글머리표 문자 직접 입력 금지(`bullets` 사용), 그라데이션·그림자·색 띠 금지.

| 내용 | 모티프 |
|---|---|
| 따라 하는 순서 | `step` (번호 원) 3~5개, 필요하면 오른쪽 단에 |
| 코드·시리얼 출력 | `codeBar` (진남색, JetBrains Mono) |
| 짧은 명령·키워드 목록 | `chip` + `para` 한 줄 |
| 선택지·걸음·결과 나열 | `numberCard` ("01"), 강조 하나만 `filled` |
| 스크린샷·배선도 | `imageCard` (흰 카드 안) |
| 증상 → 조치 | 흰 `card` + `head`(증상) + 보라 `para`("→ 조치") |
| 확인 목록 | `checkRow` |
| 시간표·규칙표 | `table` (헤더 진남색, 줄무늬) |
| 안전·고장 위험 | `warnBox` (빨간 계열) |
| 트랙·버전 구분 | `tag(s, "V1", 11.9, 1.1, d.H.accent1, 0.7)` / V2는 `d.H.accent2` |

정확한 색·크기·좌표 격자와 "하지 말 것"은 `references/design.md`. 모티프 호출 예는 `assets/example_build.js`.

## 자주 생기는 문제

- `'pptxgenjs' 모듈을 찾지 못했습니다` → 빌드 폴더에서 `npm install …` (2번). `deck.js`는 빌드 스크립트 폴더·현재 폴더에서 모듈을 찾는다.
- 제목이 두 줄로 꺾여 부제와 겹침 → 제목을 줄인다 (부제에 내용을 옮긴다). 글자 크기는 줄이지 않는다.
- 카드 안 글이 넘침 → 카드 높이를 키우거나 글을 한 줄 줄인다. 참고 덱은 글이 적고 여백이 넉넉하다.
- 색을 hex로 직접 쓸 일이 있으면 `d.H.accent1`처럼 토큰에서 가져온다. 새 색을 만들지 않는다.
